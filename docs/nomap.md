# No-map decisions — why 406 parameters have no gradient map

`docs/layers.md` registers all 500 `parameters3.md` parameters: **94 ship as
raster map layers**, **406 do not**. This file records the no-map decisions
with enough reasoning that any one of them can be challenged, re-tested, and
overturned. Every row in the appendix (§4) points at the registry file and
scorer dim that owns it; every section below states the claim, the snapshot
evidence, the near-miss proxies that were considered and rejected, and what
evidence would overturn the verdict.

## 1. The verdict standard

A gradient map is rejected (OTA PR #131 precedent) where honest calibration
cannot discriminate: a map that paints parcels on a question it cannot
resolve is fake precision, and a flat single-colour "map" of a market-wide
constant is not a map. No-map params fall into two honest kinds:

| Kind | Meaning | Count |
|---|---|---|
| **Proxy dim, no raster** | An honestly-labelled OSM-proximity scorer that differentiates listings per location, but ships without a raster master: the signal is too sparse for a county gradient, duplicates a shipped layer, or the raster build is deferred. Reasons say `kaardistatud` (mapped) + `hinnang` (estimate), never measured values. | §4 `proxy` rows |
| **NULL dim** | No honest area signal exists at all: the fact is per-listing, per-parcel, per-deal, registry-held, forensic, or buyer-side. The dim returns `None` with an Estonian check reason (`hinnang` + `EI OLE` markers, pinned by tests) naming who must check what (kuulutus, KÜ dokumendid, kinnistusraamat/notar, inspector + meter, buyer questionnaire). | §4 `NULL` rows |

## 2. How to challenge a verdict (overturn protocol)

A challenge must bring evidence, not preference. For each kind:

- **NULL → raster layer**: (1) name the snapshot feed that now carries the signal (registry added to `~/hf-data`, or OSM tag family with `osmium tags-count` proving county-wide discrimination); (2) propose bands + half/σ with a Tallinn histogram showing the median mid-ramp; (3) build the master, add the contract check, attach a screenshot; (4) open a PR against the owning batch file. A single counterexample parcel the signal mis-scores is grounds to keep the verdict.
- **NULL → proxy dim**: show the OSM tag family + counts and per-listing bands; the dim must stay `None`-safe where tags are absent (absence is thin mapping, never a measured zero — p52 floor precedent).
- **Proxy dim → raster layer**: build the walk-graph master with the dim's bands baked in, contract-check half/σ, screenshot city + rural window.
- **Any verdict**: a `parameters3.md` spec change, or proof the cited snapshot absence is wrong (re-run the quoted `osmium` command on the current PBF and paste output).

Stale-verdict risk is real and acknowledged: verdicts are calibrated to the
2026-09-12 snapshot. A verdict whose cited absence no longer holds SHOULD be
challenged — that is what this file is for.

## 3. Per-group reasoning

### G1 — Listing portals & broker NLP (40/40 no-map, all NULL)

Source: Tier 1 scraped syndication (KV.ee, City24, Kinnisvara24, Osta,
Okidoki, KVXML). Every param describes ONE listing — its price, rooms,
kitchen, finishes — never the area around it (`layers_group01a/b.ts`
headers, #202/#203). An area gradient would paint buyer-relevant
differences (this flat's garage vs that flat's none) flat: a useless map.
Closest calls considered and rejected: p28 parking from
`amenity=parking` density (area supply ≠ THIS listing's garage); p198
motor courts from parking/service density (parcel driveway design, not
supply); p412 package theft from parcel-locker proximity (risk is
stairwell regime, not locker distance); p300 flip indicators from
transaction recency (recency ≠ cheap renovation); p1/p5 from Maa-amet
medians (past area sales ≠ this asking price/bill — and not in
snapshot). Overturn: a listing-record schema wired into scoring (dims
read the kuulutus/korruseplaan instead of returning NULL) — an area map
still never follows.

### G16 — Macro, transactions & finance (44/44 no-map, all NULL)

Three sub-reasons (`layers_group16a/b.ts`, #205/#206): (1) NATIONAL
series/rules identical county-wide (Euribor, KredEx programmes,
net-metering law) — a gradient would be one flat colour, never an area
signal; (2) quarterly/annual REGISTRY tables not in the OSM snapshot
(Maa-amet medians, Statistikaamet aggregates, EMTA/KOV tax tables) —
KOV-set rates vary by municipality, but colouring KOVs without the
table in-snapshot is invented data; (3) per-deal/per-borrower facts
(rates, concessions, PMI, 1031-exchange — several US-jurisdiction
concepts with no Estonian register at all). Overturn: per-KOV tables
joined as choropleths (still not walk-graph gradients), or a
listing-schema feed for the per-deal facts.

### G18 — Spatial simulation models (22/29 no-map)

7 ship (p34/p305 dayopen/glassglare, p405/p468/p479 daylight/
fishbowl/mossrisk, p63/p181 lit/impervious exposure proxies). The rest
are **proxy dims, no raster**: solar/shade/privacy from building/tree

frontage (waterfront openness belongs to window views, not p411),
p350 lit-way winter proxy (seasonality itself UNMAPPABLE — stated, not
smoothed over). No raster because LoD2 CityGML/roof-facet physics
(PVLib + Perez on 3D facets) is not in the snapshot. Overturn: LoD2
meshes + trimesh ray-casting pipeline per building.

### G19 — On-site inspection & diagnostics (134/134 no-map, all NULL)

Tier 4 forensic facts (EVS 932 audits, DIY walkthrough with GFCI/laser/
Protimeter, EHR concealed-work records — none in the snapshot pipeline;
G19B verified by filename sweep: zero audit/NDT/interior feeds).
Every fact needs presence or a meter in THAT unit: noses, smoke
pencils, attic entry, CO worst-case tests, tape/laser measures, dark-
hours visits, rain visits, ladder touch/prod, roof surveys, drawings +
engineer (post-tension slabs — drilling blind breaks cables). A
per-unit forensic fact has no area signal by construction. Overturn:
only a per-listing inspection-report schema (EHR kaetud-tööde aktid
feed) — area maps stay invalid permanently for this group.

### G20 — Subjective buyer geography (38/38 no-map, all NULL)

Buyer-profile facts, not area data (questionnaire sliders, block
observation, gut-feeling veto). Mapping them would score the BUYER,
not the place — camera counts for p413 would measure the opposite of
a privacy attitude; one garden's soil smeared over a hectare answers
nothing. Even the two params with real alternates (p85 REL2021 grids,
p165 transient density) stay NULL: the tables/scrapers are not in the
snapshot, and faking them as area scores violates §7. Seasonal/registry
gaps (pets, lights, hoarders) have no registry at all. Overturn: wire
the questionnaire + observation protocol as buyer-side inputs (a
different surface, never a raster).
